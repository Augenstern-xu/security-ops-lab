# 安全基线审计（等保 2.0 / CIS）

> 环境：自建四节点实验集群（脱敏后：node-1 ～ node-4）
> 时间：2026.11
> 角色：独立完成

## 1. 目标与范围

- 判据来源：等保 2.0 三级「安全计算环境」+ CIS 取值
- 检查项：38 项，分 8 组（A 身份鉴别 … H 集中管控）
- 样本：152 组「项 × 主机」，适用 125 组，不适用 27 组
- 主机：4 台（node-1 ～ node-4），CentOS 8

## 2. 方法

- **判据先冻结，再测量**：38 项判据开工前写死，避免边测边改标准
- **证据四要素**：命令、原始输出、带时区的时间、精确定位（主机 + 文件/配置项）
- **定级**：`暴露面 × 影响 ÷ 修复成本`，不套 CVSS
- **可复现**：4 个只读、可重跑脚本（`baseline-ab.sh` / `baseline-cd.sh` / `baseline-efgh.sh` / `baseline-verify.sh`），任意时点重跑得到同一口径

## 3. 关键结果

- **符合率 41.6% → 77.6%**（符合 52→97，不符合 57→13；分母只算适用项 125 组），整改后完成**重启复验**
- **P0 提权链**：`~/bin/*.sh` 为 `777`，且运维账号具 `NOPASSWD:ALL`——任一本地账号改脚本即可获得 root，无需漏洞利用；`chmod 755` 后四台复验为 0
- **审计能力**：`auditctl -l` 原为 `No rules`，新增 8 条规则覆盖账号/权限/sudoers/sshd/setuid；`max_log_file` 由 40MB 调至 400MB，留存从约 5.4 个月拉到 1 年以上
- **集中日志与时间**：补齐 node-3 / node-4 的日志转发至收集端 514/TCP；四台 chrony 同步，消除时区混存导致时间线不可对齐
- **可恢复性**：`fsimage-backup.timer` 每日 03:30 抓取 HDFS 元数据 + MD5 清单，保留 7 份，并完成一次恢复演练

## 4. 未收口项与处置

13 组不符合逐条给出处置，不写"基本满足"：

- **P1 待审批（2 条）**：删除测试账号、停用图形服务——都是一条命令的事，卡在变更审批
- **风险接受（4 条）**：sudo 全权免密、主机防护、日志 TLS、监听面，写明原因与代价
- **记录在案**：其余项保留原始证据，不粉饰
- **补偿控制**：配置入 git 覆盖"配置被改能否发现"，但明确**不覆盖**二进制/系统文件替换

## 5. 我踩过的坑

- **测量错误**：复验脚本漏了 `sudo`，读不到 `0440` 的 sudoers，`2>/dev/null` 又把报错吞了——B-01 打印为空，看起来像"已经修好"。改成 `sudo -n grep` 后原文仍在
- **变更失误**：按错误判据把集中日志文件属主改成 root，rsyslog 以 logsvc 运行、写入失败，链路中断 4 分钟；改回 `logsvc:logsvc`，并把判据修订为「属主 = 运行该守护进程的账号」
- **教训**：退出码 0 ≠ 结果正确；整改脚本要幂等，前后都留实测输出，出事能立刻回滚
